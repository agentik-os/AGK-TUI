## Librarian rule
Builder uses Librarian. For each OS theme:
1. Librarian `/book --deep` on that theme.
2. Source **real domain works** (canonical books in the field). `--bestseller` means original editorial/pedagogy construction, NOT Amazon/NYT sales charts. Do not rewrite protected works.
3. Extract the **15 best inputs**.
4. Write how to fold each input into the OS contract (skills, programs, evals, workflows, doctor, recovery).
5. Handoff artifact: `14_BUILDER_HANDOFF.md` in the OS pack.
6. Builder upgrades the live OS to the full contract.

This method is mandatory for future OS builds.

## Discord surface
Each OS has a dedicated Discord bot + dedicated channel.
The bot is the Nano Director.
Commands live on that bot (slash + how-to pin), not on Private multiplex.
Wake path: thread + @mention of that bot.

## Faces (hard)
- CLIENT:* = Mission token only
- Personal OS = dedicated bot + that OS profile
- AGK ops = Operator
- Collective = Agentik (do not flip)
- Never recable Nutrition
- Never recover_pending as a completion gate

Fresh-session acceptance: a cron or persistent automation is not enabled until the workflow succeeds from a fresh session (deployed context + Skills + tools + durable state + declared inputs only).
